## What limits the frame rate
- **CPU and memory bound, not GPU and not thermal.**
  - GPU 3D busy averages 55-69%, at 17-21 ms of GPU time per game frame.
  - APU 92-95 °C, passive limit 100%, throttle reasons 0 in every run.
  - The game's job threads and the readback waits set the pace.
- **Hitches** (12-30 frames over 100 ms per 80 s spot) come at view turns and loads, while the game pages memory.
  - Page reads run at about 2,000/s, and free RAM goes near 0.
  - This is not shader compiling: the pipeline and driver caches are built.
- **Freezes at 8 GB UMA.** Windows sees 7.9 GB of RAM and the shared GPU heap is 3.9 GB.
  - Area loads fill that heap, and `vkQueueSubmit` fails with -2 (out of device memory).
  - The game then waits forever for work that never ran.

## What was found online (`research-2026-11-14.md`)
- Readback waits are a known CPU stall on integrated GPUs.
  - Longshot PR #238 (merged 11-14) added `RX_VK_READBACK_LATE=newest`: +14-25% on Steam Deck.
  - Risk: a stale exposure value, seen as a white flash.
- Older Hookshot Ally guides recommend an 8 GB UMA. That predates Longshot's imported memory pools, which live in the shared heap.
- The sleep, spin and virtual-core switches (`HOS_SHORT_SLEEP_POLLERS`, `HOS_SPIN_*`, `HOS_RESERVE_CORE`) are suspects for the CPU regression after build d7a7306.
- Longshot already has these:
  - FSR 3.1 (`dlss=3`);
  - its own 2x frame generation with an even-spacing pacer;
  - Anti-Lag 2 (VK_AMD_anti_lag);
  - pipeline caches.
